## Contract and local checks

The new boundary is `GET /api/snapshot`: `{state:"ready",snapshot:{generation_id,published_at,data_classification,read_model}}`, `{state:"empty"}`, or a 503 `{state:"error",error:"snapshot_unavailable"}`. It forwards the entire `calculate_portfolio(...).to_read_model()` JSON, including exact decimal strings, nulls, versions, FIFO lots, charges, diagnostics and observed-price provenance. Validation checks wire shape; it does no accounting. No accepted pointer is empty; a missing target/corrupt generation is an error. Nothing silently supplies demo data or zeros.

`hosted/application.ts` guards all private paths/assets/APIs using an opaque HttpOnly, Secure, SameSite=Lax `__Host-` session cookie. Only `/login` and the Google authorization entry/callback are public; `/` redirects visitors to `/login`. The login page is self-contained. All responses are `private, no-store`, deny framing and use a CSP; HEAD returns no body. Requests must match `APP_ORIGIN` exactly. Writes remain 405 after authentication and exact Origin validation. Logout is a same-origin POST that deletes the server session, so a copied old cookie stops working.

`oauth4webapi` performs authorization-code flow with state, nonce and PKCE (S256), an expiring signed HttpOnly transaction cookie, fixed Google endpoints, client authentication, ID-token issuer/audience/expiry/nonce checks and RS256 signature verification against Google's keys. Only `openid email` scopes are requested. Access/refresh tokens are never retained. Verified owner email bootstraps a durable Google subject binding in `hosted_owner_identity`; a later different subject is rejected even with the same email. Sessions are random opaque tokens stored only as SHA-256 hashes in `hosted_sessions`, expire absolutely after 30 days without rolling renewal, and are checked against the owner binding on every private request. Changing the signing secret invalidates outstanding login transactions; revoke active sessions in the database separately. Google sign-out is separate from this app's logout.

`hosted/snapshot-store.ts` uses Neon HTTP on the server. A single SQL statement joins an accepted pointer to an immutable JSON generation; PostgreSQL MVCC prevents mixed generations. New generations are append-only; a publication transaction inserts a generation and switches the pointer together. The staging seeder serializes writers with table locks, refuses all existing generations/pointers, and never alters legacy tables. Later import publication must preserve immutable generations and use version-checked pointer writes. Use a separate Worker DB role with SELECT-only access to Snapshot tables and the narrowly scoped auth grants below; keep publisher credentials in the server runner.

Prerequisites: Node 24+, npm, Python project dependencies (`requirements.txt`). From repository root:

```text

npm run hosted:test
npm run hosted:typecheck
```

The hosted build pins Wrangler 4.152.0, typechecks and uses `deploy --dry-run` to produce only a local bundle under ignored `hosted/.wrangler/`. No deploy script is run by tests/builds. The generated `hosted/synthetic.fixture` is public invented data, generated by the real canonical Python calculation, never a runtime fallback. The hosting UI deliberately displays exact strings; future presentation rounding must remain explicit and must never change execution/accounting amounts.

Test seams were approved as the authenticated application interface and visible read workflow. They do not prove live Google login, resource fit or deployed Neon connectivity.

## Reviewable configuration and secure inputs

`hosted/wrangler.toml` is a separate new Worker, not a Pages deployment. It has `assets.run_worker_first=true`; authentication cannot be bypassed by a matching static file. `workers_dev=false` and `preview_urls=false` are safe defaults. There are no committed account IDs, domains, owner emails or credentials.

Supply these privately as Worker bindings, including when reviewing a local `.dev.vars` file:

| Binding | Meaning |
| --- | --- |
| `GOOGLE_CLIENT_ID` | Google Web application OAuth client ID |
| `GOOGLE_CLIENT_SECRET` | Secret: downloaded Google OAuth Web client secret |
| `SESSION_SECRET` | Secret: cryptographically random value of at least 32 characters, used for login transactions |
| `OWNER_EMAIL` | Single verified Google owner email; first successful sign-in permanently binds its Google subject |
| `APP_ORIGIN` | Exact HTTPS staging origin, no path/trailing slash |
| `DATABASE_URL` | Secret: staging Worker role in the approved isolated synthetic Neon database, with grants below |
| `ASSETS` | Wrangler static asset binding, automatic |

All `.dev.vars*`, `.env*` and `.wrangler/` artifacts are ignored. Never use `VITE_*`, command-line credential arguments, tracked TOML, public screenshots/issues or browser storage for these inputs. Do not reuse the legacy browser connection setting. Keep schema/publisher credentials separate from the restricted Worker URL.
