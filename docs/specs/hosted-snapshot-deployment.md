## Contract and local checks

The new boundary is `GET /api/snapshot`: `{state:"ready",snapshot:{generation_id,published_at,data_classification,read_model}}`, `{state:"empty"}`, or a 503 `{state:"error",error:"snapshot_unavailable"}`. It forwards the entire `calculate_portfolio(...).to_read_model()` JSON, including exact decimal strings, nulls, versions, FIFO lots, charges, diagnostics and observed-price provenance. Validation checks wire shape; it does no accounting. No accepted pointer is empty; a missing target/corrupt generation is an error. Nothing silently supplies demo data or zeros.

`hosted/application.ts` authorizes before every method/path/asset dispatch using RS256 signature, fixed issuer/audience, required expiry/issued-at/email, 31-day maximum token age and exact owner email (case insensitive). Only the signed assertion is trusted; a plain identity header is insufficient. Missing configuration fails closed. Read and asset responses, including errors, are `private, no-store`; HEAD has no body. Writes are not implemented (405), and require an exact approved Origin before reaching that response. Future writes must retain this authorization/origin boundary and add their own validation/concurrency protection.

`hosted/snapshot-store.ts` uses Neon HTTP on the server. A single SQL statement joins an accepted pointer to an immutable JSON generation; PostgreSQL MVCC prevents mixed generations. New generations are append-only; a publication transaction inserts a generation and switches the pointer together. The staging seeder serializes writers with table locks, refuses all existing generations/pointers, and never alters legacy tables. Later import publication must preserve immutable generations and use version-checked pointer writes. Use a separate SELECT-only Worker DB role; keep publisher credentials in the server runner.

Prerequisites: Node 24+, npm, Python project dependencies (`requirements.txt`). From repository root:

```text
npm ci
python -m backend.hosted_snapshot generate
npm run hosted:test
npm run hosted:typecheck
npm run hosted:build
npm test
npm run build
python -m pytest -q
```

The hosted build pins Wrangler 4.152.0, typechecks and uses `deploy --dry-run` to produce only a local bundle under ignored `hosted/.wrangler/`. No deploy script is run by tests/builds. The generated `hosted/synthetic.fixture` is public invented data, generated by the real canonical Python calculation, never a runtime fallback. The hosting UI deliberately displays exact strings; future presentation rounding must remain explicit and must never change execution/accounting amounts.

Test seams were approved as the authenticated application interface and visible read workflow. Tests sign real synthetic RSA JWTs, substitute only external JWKS/database transports and HTTP, and exercise required fields, invalid values, authorization and visible synthetic states. They do not prove live Access policy, resource fit or Neon connectivity.
