# Private hosted dashboard feasibility

Checked 2026-10-21. Fact-finding for [Choose the frontend and backend overhaul boundaries](https://github.com/Jazenn/DEGIRO/issues/36), not a deployment or a resolved architecture decision.

## Recommended candidate

Keep React/Vite for the mobile-first interface, Neon Postgres for shared durable data, and Python/pandas in scheduled GitHub Actions for ingestion and Snapshot calculation. Add Cloudflare Workers Static Assets plus a thin authenticated API. This is a plausible zero-monthly-cost arrangement for one intermittent user, subject to measured usage and a deployment proof. No account, domain, private data, or secrets were inspected or provisioned.

The browser reads Snapshots and writes Rebalancing Targets and Crypto Scale plans through the API. It must never receive database credentials or GitHub tokens. Persist accepted stages, plan versions and completed-stage identities centrally, with transactional updates and conflict detection, so phone and laptop show the same state. Local storage can hold display preferences, not the authoritative plan. This is a proposed design, not a capability verified in the existing application.

## Verified provider facts

- Cloudflare supplies a `workers.dev` hostname without bringing a custom domain. It is intended for personal/hobby projects; Cloudflare recommends custom domains for production. Access can protect production, preview and version URLs. A paid domain is therefore optional for this personal dashboard. [Routing documentation](https://developers.cloudflare.com/workers/configuration/routing/workers-dev/)
- Access supports email one-time PINs with permitted addresses configured in an Access policy. This permits owner-only browser login without a home-network restriction. [OTP documentation](https://developers.cloudflare.com/cloudflare-one/integrations/identity-providers/one-time-pin/)
- Zero Trust offers a free tier for 50 users. Its setup documentation nevertheless requires payment details even for Free, and says that Free onboarding is not charged. A Cloudflare account, Zero Trust organization and owner setup are required. [Plans](https://www.cloudflare.com/plans/), [setup](https://developers.cloudflare.com/cloudflare-one/setup/)
- Workers Free permits 100,000 requests/day and 10 ms CPU per invocation. Static asset requests are free/unlimited; invoking code uses Workers allowances. Heavy pandas calculations belong in the existing background job, not the interactive API. JWT validation and API queries must be measured against the CPU cap rather than assumed to fit. [Limits](https://developers.cloudflare.com/workers/platform/limits/), [asset billing](https://developers.cloudflare.com/workers/static-assets/billing-and-limitations/)
- Important integration caveat: Access protects Static Assets, but their internal router does not forward `ctx.access` to the user Worker. Do not implement a combined asset/API Worker assuming that property is populated. Verify Access JWT signatures, issuer, audience and expiry at API entry, or prove a separate protected API topology. Do not trust a plain identity header. Audit all production/preview/version routes and bypass policies; test unauthenticated reads and writes. [Access integration and limitations](https://developers.cloudflare.com/workers/configuration/cloudflare-access/), [JWT validation](https://developers.cloudflare.com/cloudflare-one/access-controls/applications/http-apps/authorization-cookie/validating-json/)
- Neon's current Free pricing lists 100 CU-hours/project/month, 1 GB/project, 5 GB public transfer/project, and scale-to-zero after five idle minutes; no card is required. Some older official pages still list 0.5 GB, superseded by the October 2 storage announcement and current pricing. Frequent polling can keep compute awake. [Current pricing](https://neon.com/pricing), [storage change](https://neon.com/blog/neon-free-plan-1-gb-per-project)
- Neon documents an HTTP/WebSocket serverless driver for edge/serverless use, providing a supported connection mechanism to evaluate for the Worker API. The particular repository integration remains untested. [Driver](https://neon.com/docs/serverless/serverless-driver)
- Standard GitHub-hosted Actions runners are free for public repositories; private repositories have account-dependent included minutes/storage. Scheduled runs can be delayed or dropped under load, and public-repository schedules disable after 60 days without activity. They are suitable for periodic Snapshots, not a precise real-time trading trigger. [Billing](https://docs.github.com/en/actions/concepts/billing-and-usage), [schedule behaviour](https://docs.github.com/en/actions/reference/workflows-and-actions/events-that-trigger-workflows#schedule)

## Data consistency and remaining proof

Serve a finalized Snapshot with its valuation time, calculation version, source coverage and last successful refresh. Newer quote context may be displayed separately with its own timestamp, but must not silently overwrite only some prices inside the finalized totals or returns. Failed refreshes preserve the last good Snapshot and show staleness. This is the recommended application contract, not a provider guarantee.

Before choosing the provider definitively, prove owner login, unauthorized API rejection, preview-route protection, Worker-to-Neon connectivity, a durable plan edit visible on a second device, CPU usage, and safe secret handling with synthetic data. Confirm actual account allowances and backups/export recovery. Neither the hosting research nor provider free tiers establish that market-data coverage/licensing is free for every Asset; that remains a separate data-source check. No provider promises permanent free pricing or uninterrupted availability. No need to compare Vercel yet: the candidate already covers the required functions, and its main uncertainty is integration rather than a missing hosting capability.
