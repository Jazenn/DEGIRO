# Current valuation refresh

The authenticated `/api/refresh` operation reads one accepted generation, current shared target version and verified quote mappings. It fetches up to four EUR quotes concurrently, then revalues the reconciled quantities with Decimal.js at the canonical ledger's 40 significant digit precision. It adjusts eligible gains by market-value deltas; it does not replay Transactions, rebuild FIFO lots, infer missing cost eligibility or change recorded cash, contributions, income, fees or realized gains. Allocation percentages are display/planning inputs rounded to 12 decimal places, not execution quantities.

One PostgreSQL function locks the accepted pointer and target version, rejects concurrent changes or an expired ten-second deadline, appends an immutable generation and switches the pointer atomically. History and all reconciled accounting facts remain unchanged. Generation, ledger, settings and calculation identities travel together. Failed or incomplete batches retain the previous generation. A successful generation is reused for 30 seconds when its settings version still matches; historical work never runs in this operation.

Apply `hosted/valuation-schema.sql` only to an approved database branch. Grant the Worker SELECT on verified quote mappings and EXECUTE on the publication function, without direct publication-table writes. Populate mappings with dated broker/listing evidence; an ISIN or browser-provided ticker is not an accepted mapping. Empty synthetic staging mappings intentionally produce a retained-generation warning. The separate target schema/grants are prerequisites.

Binance uses the latest aggregate trade's string price and actual trade timestamp, as documented by the [Binance market-data API](https://developers.binance.com/docs/binance-spot-api-docs/rest-api/market-data-endpoints). Yahoo uses an explicitly verified EUR listing, unadjusted regular market price and original market timestamp; its source decimal lexeme is preserved. Retrieval never resets observation age. Crypto eligibility expires five minutes after observation, exposed both at refresh time and as `crypto_quote_eligible_until`; current prompts must compare that deadline with their own current clock. Unknown observation times fail the batch. ETF market closures retain the source date without claiming an intraday trade.

The browser reads the accepted generation before requesting an on-open refresh. Manual refresh uses the same operation. Hidden pages initiate no refresh, and there is no polling. A timed-out/failed refresh keeps the visible previous generation and reports the failure separately from finalized history.

Read-only public-provider probe on 2026-10-23: Binance BTCEUR aggregate trades returned HTTP 200 in 355 ms; Yahoo VWCE.DE chart returned HTTP 200 in 93 ms, with EUR currency and source market timestamp. These are individual observations from the development network, not hosted cold/warm or mobile-network benchmarks, a guarantee of source coverage, or verification of the owner's mappings. Live database concurrency, cold/warm authenticated end-to-end latency, actual free-tier usage and private-ledger reconciliation remain release gates. No database migration, mapping change or deployment was performed by this ticket.
